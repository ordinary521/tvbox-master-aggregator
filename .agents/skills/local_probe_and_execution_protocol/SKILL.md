# 本地真实网络探针规范与 Agent 代码修改甄别准则

本规范定义本地探针脚本的运维边界与 Agent 修改代码时的甄别标准。

---

## 1. 本地网络探针规范 (`local_probe_runner.py`)
- **云端隔离**：`local_probe_runner.py` 仅供在本地中国宽带网络环境中手动运行，绝对不写入 `.github/workflows/00_on_push.yml` 工作流。
- **零本地编译依赖**：探针脚本仅做本地 DNS 解析与 HTTP/HTTPS 连通性测试，不依赖本地 `mihomo` 编译环境。测试结果保存至 `process/local_probed_*.json` 后，通过 `git push` 交由云端 Actions 自动编译。

## 2. 代码修改与历史逻辑甄别准则
- **严禁无脑 Copy 缺陷逻辑**：参考历史提交（如 `75093de`）或模板时，必须甄别其代码逻辑。如果历史代码中存在硬编码、强加分类、缺失解转义（`\/`）等死穴，绝对禁止原封不动无脑复制代码。
- **只恢复优秀架构，剔除 Bug**：保留历史代码中优秀的配置驱动和多仓导出架构，同时剔除死穴。

## 3. 问题排查与模式隔离
- **以抓包日志与报错事实为准**：遇到网络逃逸或规则未命中，首先检查网络响应原文、转义处理以及编译后的 YAML/MRS 内容，不盲目推卸责任。
- **问答模式与执行模式隔离**：问答模式下只陈述客观事实与代码分析；收到明确修改指令后一次性落操写盘，并执行 `git commit` 和 `git push` 推送上线。
